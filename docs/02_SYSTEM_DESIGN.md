# 系统设计

## 数据流

```text
数据源
  -> 数据校验与固定划分
  -> 训练/验证/测试 DataLoader
  -> 模型与训练策略
  -> checkpoint + 原始指标
  -> 统一评测
  -> 图表、排行榜与研究报告
```

## 模块职责

### `src/data`

负责数据集注册、划分、变换和 DataLoader。它不负责创建模型，也不记录模型专属指标。

### `src/models`

负责模型定义和模型注册。模型只描述从输入张量到输出 logits 的计算，不承担训练循环。

### `src/training`

负责损失、优化器、学习率调度、单轮训练、验证、checkpoint 和训练状态。

### `src/evaluation`

负责统一指标、混淆矩阵、逐类别性能、错误样本和结果导出。

### `src/robustness`

负责噪声、模糊、遮挡等评测条件，不改变训练集和标准测试集。

### `src/calibration`

负责 ECE、Brier Score、可靠性图和温度缩放等校准方法。

### `src/compression`

负责蒸馏、剪枝、量化和效率比较。

### `configs`

配置描述一次实验，不放业务逻辑。未来每个正式结果都必须对应一份不可歧义的配置。

### `scripts`

仅作为用户入口，解析参数后调用 `src` 中的能力，避免在脚本中复制训练逻辑。

### `notebooks`

只用于探索、绘图和解释，不承担正式训练或最终评测。

## 计划中的关键接口

本阶段不定义代码，只确定职责：

- 数据构建：输入数据配置，输出训练/验证/测试加载器和类别信息。
- 模型构建：输入模型配置与类别数，输出模型。
- 单轮训练：输入模型、加载器、损失函数和优化器，输出聚合训练指标。
- 统一评测：输入模型、测试加载器和评测配置，输出结构化指标。
- 实验运行：输入完整配置，协调训练、验证、保存和最终评测。

## 依赖方向约束

```text
scripts -> training/evaluation -> models/data
robustness/calibration/compression -> models/evaluation
models 和 data 互不依赖
```

这种设计让模型、数据和实验策略可以独立替换，也便于测试。
